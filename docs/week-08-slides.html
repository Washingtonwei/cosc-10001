The big idea

Most attacks don't break the lock.
They go around it.

Everything you build will be used in ways you didn't intend, by people who don't wish you well. That's not paranoia. It's a design discipline.

MGM Resorts · September 2023

Somebody made
a phone call.

Attackers found an employee on LinkedIn, called the IT help desk pretending to be them, and asked for a login reset. Slot machines, room keys, and check-in went down across Las Vegas. MGM put the hit at about $100 million.

Nobody broke any encryption.

A threat model is four questions
  1. What are we building?
  2. What can go wrong?
  3. What are we going to do about it?
  4. Did we do a good job?

Adam Shostack. MGM's help desk was part of the system. Nobody asked question 2 about it.

Phishing

Four emails.
Real or fake?

Talk with your pod for 20 seconds, then hands up. No reveals until all four.

How to read a suspicious email
  • The display name vs. the address. "TCU IT Support" from a Gmail account
  • Lookalike domains. rnicrosoft.com is r-n, not m
  • The link vs. where it goes. Hover first; the corner of the screen tells the truth
  • Manufactured urgency. "Closes in 24 hours" exists to stop you thinking
April 2017 · the letters themselves can lie

аррӏе.com

Every letter there is Cyrillic. A researcher registered it, and Chrome and Firefox displayed it as apple.com, pixel for pixel. Chrome fixed it in version 59.

Its real name is xn--80ak6aa92e.com. You can't always trust your eyes. A password manager won't autofill on a site it doesn't recognize.

How do you check a password without telling anyone?
  1. Your computer turns it into a hash: a fingerprint that can't be turned back
  2. It sends only the first 5 characters
  3. The site sends back every leaked hash that starts that way, about two thousand
  4. Your computer finds the match on your own machine

The site never learns which one you were checking.

Before anyone types anything

This laptop. This site.
Nobody else's.

Trying this on a site you don't own is a federal crime under the Computer Fraud and Abuse Act. "I was just curious" is not a defence.

The username I typed · password left empty

admin'#

What the login page asks the database
SELECT ... FROM credential
WHERE name='$input_uname' and Password='$hashed_pwd'

It builds a sentence by pasting in what you typed.

The same sentence, with my username pasted in
WHERE name='admin'#' and Password='...'
  • My ' closed the quote early
  • # means "the rest of this line is a comment"
  • What ran: "give me the row named admin." No password check at all

The code couldn't tell data
from instructions.

I typed instructions into a box meant for data. That's the whole attack, and it has been the most famous bug on the web since 1998.

It's called SQL injection.

Same bug, different page · Alice's nickname
', salary='9999999

Every box that ends up in a SQL sentence is a door.

The fix · a prepared statement
WHERE name = ? and Password = ?

The sentence goes to the database first, with blanks. The data goes separately. Nothing you type can become an instruction.
