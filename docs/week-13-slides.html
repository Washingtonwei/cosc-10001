Writing the code is the easy part. The hard part is a hundred people building one thing without stepping on each other.

That's software engineering.

The software development lifecycle
Plan→Design→Build→Test→Deploy→Maintain↺

It's a loop, not a line. Software is never finished; it's just released.

You've already done all of it
Design: double the pile, five levels down, by handthe design session

Test: did Karel hit a wall?every Karel week

The industry just does it with more people and more coffee.

Two ways to run the loop
Waterfall. Plan everything, build everything, test everything, ship onceone big pass
Agile. Build a small piece, show it, adjust, repeatshort loops

Waterfall finds out you were wrong after a year. Agile finds out after two weeks.

Agile words you'll hear in every internship
  • Sprint: a two-week loop with one goal
  • Backlog: the to-do list for the whole product
  • User story: "As a student, I want to see my grade, so I can stop refreshing Canvas"
  • Stand-up: 15 minutes every morning. Yesterday, today, what's blocking me
The anatomy of almost every app
The cloud: someone else's computer (AWS, Azure, Google Cloud)
FrontendWhat you see and tap. HTML, CSS, JavaScript, React
⇄
BackendThe rules and logic. Spring Boot (Java!), Node, Python
⇄
DatabaseWhere the data lives. SQL, last week's session

The arrows are APIs: agreed-upon ways for programs to ask each other for things.

Follow one tap · ordering a pizza
  1. Frontend: you tap "Order." JavaScript sends your order to an API
  2. Backend: checks the store is open and charges your card
  3. Database: saves the order so the kitchen sees it
  4. Back to you: "Your pizza is in the oven" 🍕

Four layers, a few hundred milliseconds, and very likely three different teams.

Test and deploy
  • Automated tests: code that checks your code, thousands of times a day
  • CI/CD: every change is built and tested by a robot before a human merges it. The green check ✅
  • Deploy: shipping it to real users. Big companies do it many times a day

Our course site works this way. Every push runs a build that refuses broken links.
